# TECH-DESIGN-002 - Backend Gameplay Persistence and State Architecture

Status: Draft for Approval
Date: 2026-07-29

## Overview

This technical design defines the backend match state persistence, round timer strategy, reconnection state recovery payload, deterministic fixture architecture, and event consumption boundaries for Mimico V1 gameplay.

This document exists because match state management is the highest-risk area for state drift. Every frontend action, backend rule, WebSocket event, and test must agree on the same match and round state machine. Without an explicit persistence and recovery strategy, TASK-220 (backend gameplay state machine), TASK-230 (frontend authoritative gameplay UI), and TASK-240 (deterministic fixtures) cannot be implemented consistently.

## Goals

- Define match, round, and timer persistence entities and their database representation.
- Define round timer freeze/resume semantics for pause/reconnection.
- Define reconnection state recovery payload shape and endpoint.
- Define deterministic word, dice, and timer fixture interfaces for testing.
- Define word card generation strategy.
- Document accepted decisions that TASK-220, TASK-230, and TASK-240 must follow.
- Identify contract gaps or schema changes needed before gameplay implementation.
- Give TASK-220 and TASK-230 a stable implementation target without requiring back-and-forth design discovery.

## Non-Goals

- Implement any backend or frontend gameplay code.
- Choose or implement a WebRTC/video provider.
- Define full event sourcing or CQRS architecture.
- Curate a production word database.
- Design deploy, observability, or multi-repo E2E architecture.
- Change accepted SPEC-003 or SPEC-005 functional behavior.
- Define frontend state store architecture.

## Current Constraints

- Backend uses Spring Boot 3.x, JPA/Hibernate with Flyway migrations, Postgres, Redis.
- Backend already has `Match`, `MatchPlayer`, `GameRound`, `WordCard` entities with legacy field names.
- Existing `RoundTimerService` queries for expired rounds but does not handle pause correctly.
- Reconnection stores `isPaused` but not `pausedAt`, `pauseReason`, `reconnectDeadline`, or `remainingRoundSecondsOnPause`.
- Match state schema (`match-state.schema.json`) exists but lacks `pauseReason` and `reconnectDeadline`.
- Word categories are `EU_SOU`, `EU_FACO`, `OBJETO`.
- Board has 52 tiles (positions 0 = pre-board, 1-52 = playable; tile 52 = win).
- Backend tests use JUnit 5 with Mockito and optional Testcontainers.
- Frontend has a growing test suite built with Vitest and React Testing Library.

## Match State Persistence Layer

### Entity Design

The match persistence layer uses Postgres for authoritative state and Redis for transient round data and timer scheduling.

#### New and Aligned JPA Entities

| --- | --- | --- |
| `id` | UUID (PK) | generated by backend |
| `tableId` | UUID (FK → Table) | not-null |
| `matchStatus` | enum String | `MATCH_SETUP`, `MATCH_ACTIVE`, `MATCH_PAUSED`, `MATCH_FINISHED` |
| `winnerTeam` | enum String or null | `A`, `B`, or null |
| `finishReason` | enum String or null | `BOARD_WIN`, `RECONNECTION_FORFEIT`, `MANUAL_FORFEIT`, `ADMIN_CANCELLED`, or null |
| `startedAt` | Instant | set on creation |
| `finishedAt` | Instant or null | set on match end |
| `version` | Integer | optimistic lock for concurrency |

**MatchPlayer** (snapshot, immutable after match start)

| Field | Type | Notes |
| --- | --- | --- |
| `id` | UUID (PK) | generated |
| `matchId` | UUID (FK → Match) | not-null |
| `userId` | UUID (FK → User) | not-null |

| `team` | enum String | `A` or `B` |

| `expiresAt` | Instant or null | computed as `startedAt + 60s`, null until guessing starts |
| `resolvedAt` | Instant or null | set when round resolves |
| `resolution` | enum String or null | `CORRECT_GUESS`, `STEAL`, `TIMEOUT`, `MATCH_FINISHED`, `FORFEIT` |

**MatchState** (embedded in Match or separate entity)

| Field | Type | Notes |
| --- | --- | --- |
| `matchId` | UUID (PK/FK → Match) | one-to-one with Match |
| `teamAPosition` | Integer | 0-52 |
| `teamBPosition` | Integer | 0-52 |
| `currentTeam` | enum String or null | `A`, `B`, or null (before initial turn) |

| `isPaused` | Boolean | default false |
| `pausedAt` | Instant or null | set when match pauses |
| `pauseReason` | enum String or null | `PLAYER_DISCONNECTED`, `MIME_MEDIA_FAILED` |
| `disconnectedUserId` | UUID or null | the user who disconnected |
| `reconnectDeadline` | Instant or null | computed as `pausedAt + 60s` |
| `remainingRoundSecondsOnPause` | Integer or null | frozen round timer when paused |

The `reconnectDeadline` field is added to `MatchState`. The `match-state.schema.json` must be updated to include `pauseReason` and `reconnectDeadline`.

**Word**

| Field | Type | Notes |
| --- | --- | --- |
| `id` | UUID (PK) | generated or seeded |
| `text` | String | the mimeable term |
| `category` | enum String | `EU_SOU`, `EU_FACO`, `OBJETO` |

**WordCard** (embedded collection per round, or JSON column)

Decision: store word card as a join table `round_word_card` with rows `(round_id, word_id, category, selection_order)`.

| Field | Type | Notes |
| --- | --- | --- |
| `roundId` | UUID (FK → Round) | |
| `wordId` | UUID (FK → Word) | |
| `category` | enum String | `EU_SOU`, `EU_FACO`, `OBJETO` |

Rationale: a join table avoids JSONB complexity, supports referential integrity, and makes it easy to query what word was offered.

Existing backend may have legacy `Match`, `MatchPlayer`, `GameRound`, `WordCard` tables. The implementation task (TASK-220) should:

2. Leave legacy tables untouched if they are not referenced by new code.
3. Remove legacy table references from new service code.
4. Do not drop legacy tables in the same migration; defer cleanup to a follow-up if needed.

## Round Timer Strategy

### Timer Lifecycle

1. **Start**: When word is selected, set `Round.startedAt = now()` and `Round.expiresAt = now() + 60 seconds`.
2. **During round**: A scheduled task (Spring `@Scheduled`) queries `Round WHERE roundState = 'ROUND_GUESSING' AND expiresAt <= now() AND match NOT paused`. When found, trigger timeout resolution.
3. **Pause**: When match pauses:
   - Compute `remainingRoundSecondsOnPause = max(0, expiresAt - now())`.
   - Store in `MatchState.remainingRoundSecondsOnPause`.
   - The scheduled task must filter out rounds belonging to paused matches.
4. **Resume**: When match resumes:
   - Compute `newExpiresAt = now() + MatchState.remainingRoundSecondsOnPause`.
   - Update `Round.expiresAt = newExpiresAt`.
   - Clear `remainingRoundSecondsOnPause`.
5. **Timeout resolution**: When the scheduled task detects an expired round, call the timeout handler which resolves the round, switches turn, and broadcasts events.

### Scheduled Task Design

```java
@Scheduled(fixedRate = 1000) // check every second
void checkExpiredRounds() {
    // SELECT r FROM Round r WHERE r.roundState = 'ROUND_GUESSING'
    //     AND r.expiresAt <= :now
    //     AND r.match.matchState.isPaused = false
    // For each expired round, resolve as TIMEOUT
}
```

### Edge Cases

- **Timer fires during pause**: Prevented by the `isPaused = false` filter in the query.
- **Multiple disconnections during one round**: `MATCH_PAUSED` is entered once; subsequent disconnections add to a collection. The round timer remains frozen until all disconnected players reconnect or the deadline expires.
- **Match finishes while timer is running**: Timer expiry check must verify `matchStatus != MATCH_FINISHED`.
- **Remaining seconds is zero on resume**: If remaining time was 0 or negative (race condition), treat as immediate timeout.

## Reconnection State Recovery

### Endpoint

`GET /api/matches/table/{tableId}`

Returns the full `MatchState` JSON for the active or most recent match associated with the table.

If no match exists (table is in `TABLE_WAITING` or `TABLE_READY_TO_START`), return `404 MATCH_NOT_FOUND`.

### State Recovery Payload

The response body is the `MatchState` JSON conforming to `match-state.schema.json`. It must include:

- All public fields from the schema (matchId, tableId, matchStatus, roundState, players, teamAPosition, teamBPosition, currentTeam, currentMimePlayerId, timerEndsAt, isSpecialTile, isPaused, pausedAt, paused by whom, reconnect deadline).
- When the match is in word selection phase, the current mime player additionally receives a private field `wordCard` containing the 3 word options. The server delivers this through the authenticated user queue `/user/queue/match/{matchId}/word-card` rather than the shared state topic.

### Private Word Card Delivery

When `ROUND_WAITING_FOR_WORD_SELECTION` or `ROUND_GUESSING` is active:

- `/user/queue/match/{matchId}/word-card` delivers `{ type: "WORD_CARD_DRAWN", data: { wordCard: [...] }, occurredAt }`.
- Only the current mime player receives this message through STOMP user destination.
- On refresh recovery, the client should subscribe to this queue and store the word card locally until the round resolves.

### Refresh Recovery Flow

1. Client has auth token from session restore.
2. Client calls `GET /api/matches/table/{tableId}`.
3. Server returns `MatchState` JSON.
4. Client subscribes to `/topic/match/{matchId}/state` for ongoing updates.
5. If current mime player: subscribes to `/user/queue/match/{matchId}/word-card` and may receive current word card.
6. Client replaces local state with server state (no local-state-is-authoritative path).
7. Client renders active, paused, or finished state according to server.

## Deterministic Fixture Architecture

### Dice Service Interface

```java
public interface DiceService {
    int roll(); // returns 1-6
}

// Production
public class RandomDiceService implements DiceService {
    public int roll() { return ThreadLocalRandom.current().nextInt(1, 7); }
}

// Tests
public class DeterministicDiceService implements DiceService {
    private final Queue<Integer> values;
    public DeterministicDiceService(Integer... values) { this.values = new LinkedList<>(List.of(values)); }
    public int roll() { return values.poll(); }
}
```

The dice service is injected into the match service. Tests provide a `DeterministicDiceService` with known roll sequences.

### Timer Service Interface

```java
public interface TimerService {
    Instant now();
}

// Production
public class SystemTimerService implements TimerService {
    public Instant now() { return Instant.now(); }
}

// Tests
public class ControllableTimerService implements TimerService {
    private Instant current;
    public ControllableTimerService(Instant start) { this.current = start; }
    public void advance(Duration d) { this.current = this.current.plus(d); }
    public Instant now() { return current; }
}
```

All timer computations (`expiresAt`, `remainingRoundSecondsOnPause`, `reconnectDeadline`) derive from `TimerService.now()`, making them deterministic in tests without `Thread.sleep()`.

### Word Fixture Strategy

- Seed the Word table with known UUIDs via a test `@Sql` script or `@BeforeEach` insert.
- Test words are version-controlled in `src/test/resources/words/test-words.sql`.
- Every test knows word IDs by constant or enum.
- Word card generation selects exactly one word from each category. In tests, the word repository can be primed so that the random selection picks known words.

```sql
-- test-words.sql example
INSERT INTO words (id, text, category, difficulty) VALUES
    ('00000000-0000-0000-0000-000000000001', 'pular', 'EU_FACO', 'EASY'),
    ('00000000-0000-0000-0000-000000000002', 'gato', 'EU_SOU', 'EASY'),
    ('00000000-0000-0000-0000-000000000003', 'livro', 'OBJETO', 'EASY'),

    ('00000000-0000-0000-0000-000000000010', 'correr', 'EU_FACO', 'EASY'),
    ('00000000-0000-0000-0000-000000000011', 'cachorro', 'EU_SOU', 'EASY'),
    ('00000000-0000-0000-0000-000000000012', 'bola', 'OBJETO', 'EASY');
```

| Concern | Production | Test |
| --- | --- | --- |
| Dice | `RandomDiceService` | `DeterministicDiceService` |

## Word Card Generation

1. When the current mime player sends `/app/match/{matchId}/word/draw`:
   - Validate round state is `ROUND_WAITING_FOR_WORD_SELECTION`.
   - Validate actor is current mime player.
   - Query Word repository: select one random word from each category (`EU_SOU`, `EU_FACO`, `OBJETO`).
   - Persist `round_word_card` rows for the round.
   - Send word card privately via `/user/queue/match/{matchId}/word-card`.
   - The round remains in `ROUND_WAITING_FOR_WORD_SELECTION` until the mime selects.
2. Word card is valid only for the current round. After resolution, the card cannot be used.
3. Word selection (`/app/match/{matchId}/word/select`) validates `wordId` belongs to the current round's word card.

## Event Consumption Boundaries

### Server Events Published

| Event | Destination | Payload Type | When |
| --- | --- | --- | --- |
| `MATCH_STATE_UPDATED` | `/topic/match/{matchId}/state` | `match-state.schema.json` | State changes (position, turn, round, pause) |
| `WORD_CARD_DRAWN` | `/user/queue/match/{matchId}/word-card` | private word card JSON | Mime player draws word card |
| `WORD_SELECTED` | `/topic/match/{matchId}/state` | included in `MATCH_STATE_UPDATED` | Word selected, timer starts |
| `GUESS_RECEIVED` | `/topic/match/{matchId}/chat` | chat message + type: `GUESS_RECEIVED` | Eligible guess submitted |
| `CORRECT_GUESS` | implicit state event | part of `MATCH_STATE_UPDATED` | Correct guess resolves round |
| `ROUND_TIMED_OUT` | implicit state event | part of `MATCH_STATE_UPDATED` | Timer expires |
| `TURN_CHANGED` | implicit state event | part of `MATCH_STATE_UPDATED` | Turn switches |
| `MATCH_ENDED` | `/topic/table/{tableId}/closed` or match topic | envelope with winner and finish reason | Match finished |

Decision: `WORD_SELECTED`, `CORRECT_GUESS`, `ROUND_TIMED_OUT`, and `TURN_CHANGED` are not separate event types. They are conveyed as state changes within `MATCH_STATE_UPDATED`. The client observes the new `matchStatus`, `roundState`, `currentTeam`, `currentMimePlayerId`, and `roundState` to derive what happened.

Rationale: fewer event types, simpler client state machine, easier contract validation.

### Server Commands Consumed

| Command | Destination | Validator |
| --- | --- | --- |
| `SELECT_INITIAL_TURN_PLAYERS` | `/app/match/{matchId}/initial-turn/select` | Host only, match must be `MATCH_SETUP` |
| `ROLL_INITIAL_TURN_DICE` | `/app/match/{matchId}/initial-turn/roll` | Selected player only |
| `ROLL_DICE` | `/app/match/{matchId}/dice/roll` | Any current-team player, round must be `ROUND_WAITING_FOR_DICE` |
| `DRAW_WORD_CARD` | `/app/match/{matchId}/word/draw` | Current mime player, round must be `ROUND_WAITING_FOR_WORD_SELECTION` |
| `SELECT_WORD` | `/app/match/{matchId}/word/select` | Current mime player, word must belong to current card |
| `SEND_GUESS` | `/app/match/{matchId}/chat` | Must be eligible per guess eligibility matrix |

### Client Topic Subscriptions

| Topic | Subscriber | Purpose |
| --- | --- | --- |
| `/topic/match/{matchId}/state` | All match players | Receive `MATCH_STATE_UPDATED` |
| `/topic/match/{matchId}/chat` | All match players | Receive guesses and chat messages |
| `/user/queue/match/{matchId}/word-card` | Current mime player only | Receive private word card |
| `/topic/table/{tableId}/closed` | All table players | Receive `MATCH_ENDED` or `TABLE_CLOSED` |

Add new event messages:

- `MatchPaused` → `/topic/match/{matchId}/paused` (optional separate topic; alternatively the pause is conveyed through `MATCH_STATE_UPDATED` with `matchStatus: MATCH_PAUSED`)

## Accepted Decisions

These decisions are accepted and must be carried into TASK-220, TASK-230, TASK-240, and any related implementation tasks.

| ID | Decision |
| --- | --- |
| `TECH-DESIGN-002-AD-001` | Match state is persisted in Postgres via JPA entities; Redis is not required for authoritative state in V1. |
| `TECH-DESIGN-002-AD-002` | Round timer is server-authoritative with `roundExpiresAt`; clients display remaining time from server state. |
| `TECH-DESIGN-002-AD-003` | Timer freezes during pause by storing `remainingRoundSecondsOnPause` and computing a new `expiresAt` on resume. |
| `TECH-DESIGN-002-AD-004` | Pause state, disconnection, reconnect deadline, and reconnection timeout are managed through `MatchState` fields, not a separate pause entity. |
| `TECH-DESIGN-002-AD-005` | `DiceService` and `TimerService` interfaces enable deterministic testing without randomness or sleep. |
| `TECH-DESIGN-002-AD-006` | Word card is delivered privately through `/user/queue/match/{matchId}/word-card` and is never broadcast to all players. |
| `TECH-DESIGN-002-AD-007` | Gameplay events (word selected, turn changed, round resolved) are conveyed through `MATCH_STATE_UPDATED`, not separate event types. |
| `TECH-DESIGN-002-AD-008` | Word card uses a join table `round_word_card` for referential integrity; JSONB is not required. |
| `TECH-DESIGN-002-AD-009` | `GET /api/matches/table/{tableId}` is the state recovery endpoint for reconnection and refresh. |
| `TECH-DESIGN-002-AD-010` | New Flyway migrations create aligned entities alongside (not replacing) legacy tables; legacy cleanup is deferred to a follow-up task. |
| `TECH-DESIGN-002-AD-011` | Match mime rotation uses `lastMimeRound` per `MatchPlayer`; the player with the lower value on the team is selected next. |

## Risks And Mitigations

| Risk | Mitigation |
| --- | --- |
| Timer race condition between `@Scheduled` and pause signal. | Use `isPaused = false` filter in the expired-round query; pause handler sets this flag before the next tick. |
| Legacy table coexistence creates confusion. | New services use new entities only; old tests continue against old entities. A follow-up removes legacy tables. |
| Word card delivered to wrong client. | Use STOMP user destination (`/user/queue/...`) which Spring WebSocket routes by authenticated session. |
| Concurrency on match state during high-frequency commands (dice, guess). | Use optimistic locking (`@Version` on Match entity) and retry on `OptimisticLockException`. |
| Reconnection deadline computation drifts under heavy load. | `TimerService.now()` gives the authoritative time source; scheduled timeout task runs every second. |

## Acceptance Criteria

Implementation of this design is complete when:

- Match, MatchPlayer, MatchState, Round, WordCard, and Word entities exist with the fields defined above.
- Round timer freezes on pause and recomputes expiresAt on resume.
- `DiceService` and `TimerService` interfaces support deterministic injection.
- Scheduled task resolves expired rounds only when match is not paused.
- `GET /api/matches/table/{tableId}` returns canonical match state.
- Word card is delivered privately to the mime player via `/user/queue/match/{matchId}/word-card`.
- `match-state.schema.json` includes `pauseReason` and `reconnectDeadline`.
- AsyncAPI includes `WORD_CARD_DRAWN` user queue and `MATCH_ENDED` event.
- Spec-map, EXECUTION-STATUS, or both reference this Tech Design as active or accepted.
